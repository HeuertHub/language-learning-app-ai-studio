# Exercise Engine Architecture: Phase 3B.3 Runtime Implementation

**Status**: Implemented & Certified  
**Authority**: Senior Software Engineer / Lead Curriculum Architect  
**Target Codebase**: React 19 / TypeScript / Vite / Firebase Firestore  

---

## 1. Architectural Overview

The Exercise Engine provides the runtime execution and evaluation foundation for the authoritative 1,257-lesson Mongolian language curriculum across the entire CEFR continuum (**Pre-A1 through C2**).

The engine operates on a strict separation of concerns:
1. **Frozen Pedagogical Blueprints (`curriculum/blueprint/**` and `curriculum/lesson_blueprints/**`)**: Cryptographically checksummed immutable sources of truth defining unit boundaries, lesson objectives, CEFR competencies, and vocabulary/grammar budgets.
2. **Derived Runtime Curriculum Assets (`public/data/**`)**: Deterministic, reproducible runtime JSON assets generated by `scripts/build_runtime_curriculum.py` for direct consumption by the client application.
3. **Authoritative TypeScript Contract (`src/types/exerciseEngine.ts`)**: Type definitions for exercise definitions, modalities, interaction patterns, cognitive complexities, and evaluation rules.
4. **Authoritative Single Evaluator (`src/utils/evaluationEngine.ts`)**: Linguistic normalization, token order comparison with punctuation separation, multi-select set equality, harmonic suffix attachment, and dual-layer qualitative rubric assessment.
5. **Universal Interactive Renderer (`src/components/LessonView.tsx`)**: Renders all 9 supported interaction patterns, handles user input via virtual Cyrillic keyboard or physical keys, and coordinates safe audio playback.

### 2.2 Supported Interaction Patterns (`InteractionPattern`)
The engine implements 9 discrete interaction patterns:
1. `MULTIPLE_CHOICE`: Single-selection multiple choice across curated distractor sets.
2. `MULTI_SELECT`: Multi-selection evaluation using set equality (`SET_EQUALITY`).
3. `PAIR_MATCHING`: Grapheme and vocabulary paired association.
4. `TOKEN_REARRANGEMENT`: Head-final Mongolian SOV sentence construction via clickable word tokens.
5. `CLOZE_TEXT`: In-sentence gap filling with Cyrillic text input and on-screen keyboard assistance.
6. `SUFFIX_ATTACHMENT`: Morphological suffix attachment based on back/front vowel harmony.
7. `AUDIO_COMPREHENSION`: Spoken Cyrillic listening comprehension with speech rate controls.
8. `AUDIO_DICTATION`: Phonetic transcription of dictated Cyrillic words and phrases.
9. `OPEN_RESPONSE_RUBRIC`: Advanced rhetorical and statutory synthesis evaluated via qualitative rubric criteria.

### 2.3 Cognitive Complexities (`CognitiveComplexity`)
Aligned with Bloom's Revised Taxonomy adapted for second-language acquisition:
- `IDENTIFY_RECOGNIZE`
- `DISCRIMINATE_PHONEMES`
- `RETRIEVE_MATCH`
- `APPLY_MORPHOLOGY`
- `ANALYZE_SYNTAX`
- `PARSE_LEGAL_DISCOURSE`
- `EVALUATE_PRAGMATICS`
- `SYNTHESIZE_CRITIQUE`

### 2.4 Match Types (`MatchType`)
- `EXACT`: Strict character-by-character equivalence.
- `TOKEN_ORDER`: Ordered list equivalence with punctuation separation and whitespace normalization.
- `NORMALIZED_TEXT`: Case-insensitive, whitespace-normalized, punctuation-stripped comparison.
- `SET_EQUALITY`: Unordered set comparison for multi-select options.
- `RUBRIC_CRITERIA`: Two-layer evaluation separating completion validation from qualitative criteria.

## 3. Linguistic Normalization & Evaluation Safeguards

Implemented in `src/utils/evaluationEngine.ts`:

1. **Unicode NFC & Whitespace Normalization**:
   All string inputs are normalized using standard Unicode NFC composition. Multiple whitespace characters (spaces, non-breaking spaces `\u00A0`, tabs, newlines) are collapsed into single spaces.
2. **Punctuation Independence**:
   Token evaluation (`separateUiPunctuation` and `compareTokensPunctuationIndependent`) strips leading/trailing commas, periods, quotes (`«`, `»`, `"`, `“`, `”`), dashes, and colons so learners interact purely with linguistic morphemes.
3. **Acceptable Alternatives (`acceptableAlternatives`)**:
   Evaluator inspects alternative orthographic or dialectal forms specified in the exercise metadata.
4. **Inflected Variants (`allowInflectedVariants`)**:
   Allows root-stem matching when inflectional variation is permitted by the pedagogical rule.

## 4. Dual-Layer Rubric Evaluation

For C1/C2 writing and synthesis exercises (`OPEN_RESPONSE_RUBRIC`, `RUBRIC_CRITERIA`):
- **Layer A (Completion Validation)**: Checks that the learner has provided a substantive response (minimal character threshold). Once satisfied, marks the exercise as completed for session progression.
- **Layer B (Qualitative Assessment)**: Rather than falsely labeling arbitrary text as linguistically flawless, the UI presents the authoritative rubric criteria (criteria names, descriptions, point weights) alongside an interactive self-reflection checklist for learner metacognitive analysis.

---

## 5. Audio Safety Architecture

Implemented in `src/utils/audio.ts`:
- **Zero Foreign-Voice Fallback**: Strictly searches only for authentic Mongolian voices (`v.lang.startsWith('mn') || v.lang.toLowerCase().includes('mongol')`).
- **Elimination of Slavic Interference**: Russian, Ukrainian, and Bulgarian voice fallbacks are completely eliminated to prevent palatalized pronunciation interference with Khalkha Mongolian vowel phonemes (especially Ө `[œ]` and Ү `[ʏ]`).
- **Web Audio Formant Fallback**: When no system Mongolian voice is installed on the user device, the engine synthesizes acoustic formant tones (`F1`, `F2` frequencies) via native Web Audio API oscillators.

## 6. Runtime Curriculum Data Pipeline

The build pipeline (`scripts/build_runtime_curriculum.py`) converts frozen blueprints into static runtime assets in `/public/data`:
- `curriculum_manifest.json`: Top-level catalog of all 26 sections, 256 units, and 1,257 lessons.
- `sections/section-01.json` ... `section-26.json`: Granular section data with fully populated unit and lesson metadata.
- `pilot_exercises.json`: Authoritative pilot exercises linked by `lessonId`.
- `course_full.json`: Complete bundled curriculum object enabling instant single-request loading.

If runtime asset loading fails, the production application displays a visible error screen with retry capabilities, strictly preventing silent fallback to obsolete prototype datasets.
